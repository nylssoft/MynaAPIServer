# Appointments API

Appointments support authenticated owners and invited participants. Owner operations send the owner's login token in the `token` header. Participant operations use the appointment's `accesstoken` header; this access token is sensitive and grants access to that appointment.

## Owner operations

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/appointment` | List appointments owned by the signed-in user. |
| `POST` | `/api/appointment/{uuid}` | Create an appointment using a JSON `AppointmentModel`. |
| `PUT` | `/api/appointment/{uuid}` | Update an owned appointment using a JSON `AppointmentDefinitionModel`. |
| `DELETE` | `/api/appointment/{uuid}` | Delete an owned appointment. |
| `GET` | `/api/appointment/{uuid}/accesstoken` | Generate a participant access token for an owned appointment. |
| `POST` | `/api/appointment/batch` | Fetch/delete a bounded batch of appointments using per-item UUID and access token. |

An `AppointmentDefinitionModel` contains a `description`, `participants` array, and `options` array. Use the model returned by the API as the basis for updates; the description and at least one valid future option are required. Once votes exist, participant changes are restricted: participants can be added but existing participants cannot be removed.

## Participant operations

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/appointment/{uuid}` | Read an appointment using its `accesstoken` header. |
| `PUT` | `/api/appointment/{uuid}/vote` | Submit/update a JSON `AppointmentVoteModel` using `accesstoken`. |
| `GET` | `/api/appointment/{uuid}/lastmodified` | Get the last-modified timestamp using `accesstoken`. |

A vote contains a participant `userUuid` and an `accepted` array of options; each option identifies a year, month, and list of days. Vote changes update the appointment's modified timestamp. The token can be generated by the owner endpoint and should be shared only with intended participants. The server encrypts stored definitions and votes using key material carried in the access token; treat the access token as a secret and send the documented JSON models normally.

Invalid tokens or inaccessible appointments are rejected. Validation errors use Problem Details; batch size and UUID lengths are bounded by server limits.
